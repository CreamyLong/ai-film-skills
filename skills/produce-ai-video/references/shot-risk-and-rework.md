# 镜头风险与返工止损

返工贵，不是因为模型慢，而是因为用“再改一版提示词”去解决结构问题。本文件规定：什么必须先预检、什么值得重渲、什么时候必须改镜。

## 1. 提交前先跑结构预检

```bash
python3 scripts/shot_contract_check.py --prompts <prompt-set.json>
```

它不调用模型，只查会在渲染后变成整镜报废的结构问题：

| 代码 | 含义 | 处理 |
|---|---|---|
| `PICTURE_COUNT_MISMATCH` | `<Picture N>` 与参考图张数不符 | 重排编号，删掉过期句子 |
| `DETAIL_REF_IS_PORTRAIT` | 把整张肖像标成“局部/伤疤特写” | 删掉该参考或换成真正的局部图 |
| `ALTERNATING_SPEAKERS` | 一个镜头里两个人交替说话 | 拆成每人一镜；若坚持同框，记录为已知风险 |
| `DIALOGUE_PLUS_PROP_ACTION` | 同一镜既说话又开抽屉/递文件/扔东西 | 拆动作与台词，或删掉动作 |
| `TEXT_PROP_IN_CLOSEUP` | 带字文件/封面/图纸成为特写主体 | 闭合、背面、移出画框、失焦，或后期插静态图 |
| `MISSING_ENVIRONMENT_ANCHOR` | 写了房间/街道却没有环境参考 | 补场景图或视频参考 |
| `UNANCHORED_FOREGROUND_PERSON` | 前景人物没有角色定义/参考 | 补参考或删掉前景人 |

`block` 必须在提交前改结构；`review` 是已知风险，要在生产记录里写明“接受/拆分”。

## 1.1 跨镜连续性文字校对

同一场多个镜头**写清站位后再提交**：每个双人镜声明谁在哪侧（"Shen Guodong sits on the right side of the frame"）。然后跑：

```bash
python3 scripts/continuity_audit.py --prompts <prompt-set.json> --shots 03,04,09
```

它把各镜头的 detailed_description 按角色汇总，问决策模型站位/服装是否一致。实测：修复版 EP012（声明了站位）pass；人为把 shot09 的父亲翻到左侧后立即报 `AXIS_CONFLICT`（agree=0.377）。这能在烧 GPU 前抓住轴线翻转和服装矛盾。注意：提示词不声明站位它无从判起——**先声明，再校对**。

### 1.2 提示词风险扫描

```bash
python3 scripts/prompt_risk_scan.py --prompts <prompt-set.json>
```

渲染前用决策模型对每镜的 `detailed_description` 评三个实测风险类：台词+多动作竞争、带字道具成焦点、站位/机位欠声明（P≥0.7 block，0.4–0.7 review）。EP012 回测：pass 版 shot07 干净；带风险的旧镜被标出。诚实的边界：它不是“完美提示词”的证明——生成有随机性，它只压缩已知失败类的概率；且它漏抓过 shot07 v1 的历史案例（短描述下能抓到 0.90，全段上下文下信号被稀释），所以它是 review 级辅助，不是单独的门。

## 2. 失败分类

拿到 `auto_review` 或人工看片结果后，先归类，再决定动作：

| 类型 | 例子 | 允许的动作 |
|---|---|---|
| 措辞/光线 | 过暗、构图偏、动作幅度小 | 改一次措辞，保留 seed，重渲 |
| 资产 | 场景缺件、角色图错、服装文字乱码 | 先修资产，再渲；不要用提示词补 |
| 结构 | 说话人对调、同镜多动作、带字道具特写、画面多出人 | **改镜**：拆镜、删道具、换机位，不靠改词 |
| 随机 | 单帧手部畸形、轻微闪烁 | 可接受则记录 minor；不可接受才重渲 |

## 3. 止损规则

- 第 1 版失败：只允许一次“同结构改措辞”重渲；
- 第 2 版仍失败：**停止改词，必须改结构**；
- 同一构图不允许出现第 3 版；
- 每次重渲只改一个变量（提示词 / seed / 参考图三选一），否则无法判断哪次有效；
- 重渲前重跑 `shot_contract_check.py`，结构仍为 `block` 就不提交；
- 重渲后只审 `block`/`major`；`minor` 记录后放行，不因小瑕疵反复重渲。

## 4. 改镜优先级

结构失败时按这个顺序改，成本从低到高：

1. 删掉非必要动作或道具（例：父亲只说话，不开抽屉）；
2. 拆成两个单人镜，各说一句（例：14A/14B）；
3. 换机位/景别，避开带字道具或未锚定前景；
4. 改成后期静态插入（可读文件、图纸、手机屏）；
5. 最后才换 seed 或重建资产。

## 5. 记录字段

每次尝试写一行，便于判断是否该止损：

```json
{"shot":"07","attempt":3,"change":"removed drawer action","failure_class":"structural",
 "verdict":"pass","seed":27007,"cost_minutes":18}
```

同一镜出现两次 `structural` 失败，下一次必须改镜，不允许继续调措辞。

## 6. 草稿分辨率门

正式分辨率之前，用同 prompt、同 seed、同步数渲一版 **512×896**，只检查结构：

| 检查 | 草稿能查 | 草稿不能查 |
|---|---|---|
| 人数、身份、服装 | 是 | — |
| 构图、景别、轴线 | 是 | — |
| 空间/光源是否同一间房 | 是 | — |
| 道具是否出现/缺失 | 是 | — |
| 手指、文字、细纹理 | — | 否 |
| 最终清晰度 | — | 否 |

实测 EP012 shot07：512×896、8 步，约 6 分钟；768×1344 同镜约 18 分钟，约 3 倍差距。草稿 `auto_review` 为 pass，身份、服装、构图与正式版一致；但草稿偏软，不能当成交付或最终验收。

规则：

- 草稿 `block` → 不渲正式版，先改结构；
- 草稿 `pass` → 渲正式版，并用同一条审核再判一次；
- 草稿与正式版构图可能略有差异，不能拿草稿帧替代正式版复查；
- 草稿不能用于验收文字、手部或细节。

## 7. 与现有门的关系

| 门 | 负责 |
|---|---|
| `shot_contract_check.py` | 提交前的结构风险 |
| `shot_preflight.py` | 镜头交接、台词预算与映射 |
| `auto_review.py` | 渲染后的身份/空间/伪影/台词分诊 |
| 本文件 | 失败后的动作选择与止损 |
