# 视频提交前审核与连续性闭环

## 适用范围与证据

仅在用户明确授权实际视频生产或视频测试时，对每次视频模型提交、拆分单元和重试运行本门；批量任务中每个单元各有结论。文字分镜、提示词或工作流咨询可按现有阶段交付，不因资产未生成而伪称可以提交，也不因此启动生图、上传或付费。关键帧生成前先过本门的资产部分，关键帧完成后另过 `keyframe-visual-review.md`。批量放大还须通过 `pregeneration-quality-gate.md`，两门互不替代。

本门由执行者运行；`scripts/shot_preflight.py` 与 `scripts/prompt_preflight.py` 是各自范围内的本地检查，不是自动拦截模型调用的程序，也不替代语义、资产或媒体审核。实际视频提交时分别按 `shot-audit-protocol.md` 和 `prompt-compilation-preflight.md` 准备并运行；程序不可运行或输入无法核实时，相关要求保持 `UNVERIFIED`。比较两份报告针对同一实际投送文本的 SHA-256，不能用一份检查旧分镜、另一份检查新提示词。分别记录实际读取的剧本版本与覆盖范围、资产及版本、真实参考文件与审批、片段边界、目标模型及能力依据、提交文本与附件、审核人和结果。核不到的标 `UNVERIFIED`，不得把文件名、提示词、计划生成的图片或他人转述当成已经查看和批准的证据。材料只覆盖局部时声明范围；可能影响当前段的跨集事实或上一段尾态缺失时，先补证据或停在待验证，不猜填。

## 1. 资产准备门

逐个核对当前提交涉及的资产，记录身份、版本、实际参考、批准状态、变体和本次用途；参考图、参考音频须确实能读取且具备使用权限。只对适用资产检查，不要求无对白镜头制作配音或给不存在的道具建卡。

- **人物**：按本包硬规则，每个涉及角色在关键帧前须有已锁定的正面、精确90度侧面、背面全身及中景参考；确认同一身份、服装、发型和当前受伤等变体对应剧情时间。缺任一视图或未批准时停在资产完成，不以单张好图代替。
- **场景**：每个实际使用的场景准备已审核的同一空间主图和反打图，核对门窗、固定物、光源、尺度与方位；当前镜头覆盖不到的必要区域另补匹配角度，不能用同图裁切冒充新视角。若抽象空间或素材本身不支持反打，须有明确的用户确认替代依据和覆盖范围；未确认不提交该场景。
- **道具**：剧情或镜头需要的道具有已审核的身份、形制、关键可见面、持有人、初末状态和相应参考；存在版本、数量、损坏或换手时核对其时间和变化。
- **声音**：有对白时为每位说话人锁定可用音色方案、语言/口音、台词和使用权；需要音频参考或声音克隆时，确认相应模型支持、真实参考及明确授权。无对白、原生音视频、外部配音和刻意静默按实际路线核对，不能把未生成的音频当成已试听通过。环境声、音效、音乐按需要核对来源、空间关系和授权，不凭空增添。

资产不齐时列缺项和负责环节，在已授权范围内完成并重新审阅；超出生成、费用、声音权或上传授权时先请求授权。用户只要求文字提示词时，可交标明待补资产的候选文本，不标为生成就绪。

## 2. 剧情与交接门

建立或恢复与本次范围相关的连续性账：集/场/片段顺序与故事时间、世界规则、人物在场位置和知情/目标/关系、伤势与服装、道具持有和状态、因果事件、伏笔及揭示、声源与环境变化。区分原文事实、用户锁定、候选假设和未知，标注来源。局部修改复用版本未变的记录，并读取受影响的原文和上下游；不能只看本段提示词宣称全剧已审。

逐项核对：

1. 本段戏剧目标、关键行动和结果可理解，事件先后、人物动机及其获得的信息有依据；人物不能使用尚未获得的信息，重要解法有铺垫。
2. 每个相邻片段和相关集之间，前一尾态与后一首态的变化有画内动作、可信的画外时间/机制或明确叙事转场；人物进出、道具交接、位置、时间和声音变化可追溯。
3. 闪回、蒙太奇、省略和有意跳切可以改变时间或空间，不要求像素相同或补拍所有过程；但不能仅以“蒙太奇”掩盖因果断链，也不能把未说明的变化当作已验证。
4. 提示词保全已锁定动作、台词、镜序、时长及前后状态；不合理的结构若属于用户锁定项，说明冲突及后果，提出候选并等待授权，不擅自改剧情。

发现按严重度、集/场/片段与证据、影响、修订目标、责任层记录；重大冲突或缺乏必要证据阻断提交。回到最早错误层修复，检查受影响下游，不能靠增加华丽细节掩盖叙事问题。

对已有分镜与生成稿逐镜建立“源事实/镜头设计/实际投送”对照：逐句检查声音路线及原话、谁持有关键物件、交接发生在何处、上一镜真实尾态是否被错记为本镜开场；重要推断查角色获取依据。镜头间时间与地点跳跃可以省略普通动作，未展示不等于不合理；关键变化若缺依据标待核实，不伪造画外事件或提前揭开悬念。

## 3. 精确提交门

对即将发送的实际提示词、图片/声音附件、参数和目标模型逐一反查：身份及场景引用是否真实附带、道具/动作/接触/反应/尾态是否可观察、镜头与光源是否符合世界状态、关键台词与声音是否映射、时间和模型限制是否兼容、正负约束是否冲突。按 `prompt-compilation-preflight.md` 记录增强范围、内容来源、回退状态、逐文件引用及审核哈希，核对转换前后是否增添或改写了锁定事实。细节服务剧情、材质、表演、光线和可读性；不为“细节拉满”加入与锁定项冲突的天气、人群、对白、音效或不必要的动作。

每次记录 `PASS`、`REVISE` 或 `BLOCK/UNVERIFIED`，并列证据、问题位置、影响、修订归属和待办。只有适用硬条件均已验证且授权、预算、外部传输和声音权均满足，才可提交；风格口味与可选增强不自动升级为阻断项。记录本次实际文本、参数、附件及依赖版本的标识；提示词、参考、模型参数、上游剧情或相关资产改变后，本次结论失效，重新检查受影响项及完整提交包，再作出提交决定。不要将先前通过当作新版本的通行证。

发现台词或动作从设计稿漏到投送稿时，按已确认的声画路线补回实际输入；不能执行原生声音时明确使用获授权的后期声轨，别只写“人物说话”。台词时间先依据试读或现有录音含停顿核对可用窗口；未计时标待验证，不使用统一字数/秒作为合格线。若原台词、镜数或时长已锁且无法共存，展示冲突与可选方案并等待授权，不静默删台词或改剧情。

## 4. 生成后与跨集复核

视频返回后实际观看当前片段并对照剧本、资产和提示词：核对关键动作、反应、台词、身份、道具、光线及状态变化；查看相邻实际片段的切点、尾帧和首帧，不只比较文字。关键帧逐帧审核之外，动态片段按正常速度连续播放，必要时慢放或逐帧定位手物接触、运动和穿帮；抽帧不能证明帧间动作连续，也不声称检查手段能保证每一帧绝无问题。

跨集比较相关已验收的实际片段、人物/场景资产和故事状态；有意变化按剧情时间和依据判定，不因镜头或场景切换自动判错。素材或播放能力不足时标 `UNVERIFIED`，不把引用同一资产当成实际一致性的证明。发现问题按剧本/导演、资产、镜头、提示词、素材、剪辑或声音分流，在授权和预算内修复；重新核对受影响的前后片段、集间交接及最终渲染。最终按 `qualified-video-acceptance.md` 完整看片和复看，未通过或缺证据不得称合格成片；用户审美接受另行确认。
