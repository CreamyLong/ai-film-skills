# 用多模态审查模型做渲后分诊

适用于支持图片、视频、音频输入且只输出文本的 omni 模型（实测：`qwen3.8-omni-flash`，OpenAI 兼容端点）。它负责“再看一遍并指出证据”，不负责判合格。

## 1. 能可靠做什么

实测通过、可复核的四类：

| 任务 | 送法 | 输出要求 |
|---|---|---|
| 角色身份 | 角色参考脸 + 该镜单帧 | 是否同一人；不是则列至少三处面部/造型差异 |
| 烧录字幕 | 六帧或十二帧抽检网格 | 第几帧、文字内容、画面位置 |
| 空间连续性 | 同场 10–12 帧网格（带时间码） | 墙面、座椅、人群、光源、陈设逐项是否连续 |
| 机位运动 | 5–10 s 原片 | 固定还是推拉摇移；方向与幅度 |

辅助可用：台词转写、音色/情绪描述、单镜人数与说话状态。

## 2. 不可靠、必须换问法

- **跨帧换脸**：同一张网格里容易判“同一人”。身份必须用“参考图 vs 单帧”成对送。
- **切点音频**：单段音频常答“没问题”。必须一次送两段（问题段 + 正常段）做 A/B，问“哪一段、第几秒、哪种断裂、1–5 分”。
- **人群位置变化**：生成随机性会被写成“空间跳变”。只接受能指到墙面/徽标/固定陈设的结论。
- **表演与节奏**：不要让它判“好不好看”。

## 3. 送检规格

- 视频：单次 ≤10 s、≤5 MB；整集按场景切片，或改用 1 fps 网格。
- 网格：每帧带时间码；6 帧用于字幕，10–12 帧用于空间。
- 音频：16 kHz 单声道 WAV，切点前后各 2 s；成对送。
- 提示词只问一个任务，要求“逐帧/逐秒 + 证据”，禁止开放式的“评价一下”。

## 4. 结果处理

1. 每条结论必须能落到具体帧号或秒数；落不到的不采信。
2. 模型输出进 `review_required`，人工看那一帧/听那一秒后才改 `reviewed`。
3. 与机械门分工：`caption_preflight`、`speech_route_check`、`audio_continuity_check` 先跑；omni 只补“语义/空间/身份”这类机械门测不出的问题。
4. 记录模型名、调用时间、输入文件哈希和原始回答，便于复现与追责。

## 5. 成本控制

- 一个对白特写 = 1 次双图调用；一场空间 = 1 次网格；一个场景切换 = 1 次 A/B 音频。
- 单集控制在 5–8 次调用；主 key 镜才送原片。
- 不要把整集视频直接上传；token 与延迟都会失控。

## 6. 密钥与合规

- 只从环境变量读取密钥，不写入仓库、脚本、命令历史或报告。
- 上传的帧、音频、视频属于制作素材；确认服务条款允许后再送，敏感项目先脱敏或改用本地模型。
