# 生产台账与提交门禁

## 目的与边界

台账把从原著到全片的产物登记为带哈希、依赖和审核记录的条目。上游内容变化后，依赖它的下游条目自动失效；提交模型前，网关核对实际请求、附件字节和已审依赖。

台账和网关只证明**登记、哈希、依赖、版本和请求一致**。它们不看图、不听音、不理解剧情，也不能阻止绕过脚本的直接调用。审核结论必须来自人工或宿主的独立复核，并以证据文件登记。

## 台账：production_state.py

命令从 JSON 文件读取，不把私密值放进 shell 参数：

```text
python scripts/production_state.py --state <台账.json> --command <动作.json>
```

动作：`init`（只创建，不覆盖）、`register`、`review`、`status`、`reserve`、`receipt`、`bind`。

| 类型 | 审核域 |
|---|---|
| source | coverage |
| screenplay | story |
| director | directing, continuity |
| asset | asset |
| animatic | story, pacing |
| keyframe | visual, continuity |
| submission | semantic, assets, keyframes, audio, capability, authorization, continuity |
| video | visual, audio, continuity |
| scene | picture, sound, continuity |
| film | story, picture, sound, continuity, delivery |

- `register` 记录文件的 SHA-256 与依赖。依赖以其当前指纹被钉住；内容变化使条目版本递增，下游标记为过期并清空审核。
- `review` 只接受 `accepted` 或 `rejected`，必须写明 `authority`（`user` 或 `delegated`）和 `reviewer`，证据文件的哈希同时记录。若条目或依赖不就绪，不能接受。
- `status` 只报告 `ready` 与问题列表，并标注未进行媒体分析。
- 媒体类条目（keyframe、video、scene、film、animatic）必须指向真实本地文件；登记只代表“这个字节存在”，不代表合格。
- 台账文件有独占锁。锁被占用时停止；不得删除他人的锁，确认无进程占用后由操作者手工处理。

## 提交网关：submission_gateway.py

`describe` 只读取图和输入文件，不提交：

- 节点必须在白名单内；未知节点直接拒绝。
- 解析 H3 时间线，计算每个实际附件的 SHA-256。
- 按 H3 清单顺序镜像标签：图片、视频参考、独立音频，再到每个视频参考中原片的配对音频（`derived`）。
- 不支持或无法证明的内容直接拒绝，不截断、不猜测：锁定配乐、非 `guide` 模式的视频参考、超过 15 秒的视频参考、区间外片段、超过容量的图片或音频。

`checked` 在提交前要求：

- 提交记录已登记并就绪，其依赖包含导演、资产和关键帧；整片范围还需剧本、预演，以及未豁免时的原著来源。
- 附件与依赖按字节匹配：每个附件必须等于某个已审依赖的哈希。第一张构图参考必须是已审关键帧。
- 声明的附件顺序、角色、路径和哈希与实际请求完全一致；配对音频不能省略。
- 有台词的原生音频镜头，说话人必须有已审、且实际挂入请求的音色资产。
- 提示词预检与逐镜结构预检不得有阻断项；审核项必须有依赖中的证据解决，并与发现内容的哈希一致。

`prepare` 通过后，参考文件复制为内容哈希命名的不可变快照，请求改用快照路径，再预留一次提交（`reserve`）。

## 提交结果与未知状态

提交记录依次经过 `reserved` → `submitted` → `completed` 或 `failed`。

- 服务端结果无法与已审请求核对、或网络异常后无法确认时，记为 `unknown`。
- `unknown` 不自动重提，也不把同一请求当作失败重试。操作者须先核对服务端历史，再手工登记结果。
- 任何 `failed` 之外的未完成尝试都会阻止同一指纹再次预留。
- 成功结果经 `bind` 登记为新的待审视频条目，依赖提交记录；它不继承审核。

## AIFilm 接入

AIFilm 的 `tools/production_gate.py` 是本地宿主适配器，不属于本 Skill 包。它负责调用上述函数并固定运行时文件：

- 登记条目的类型约定：角色、场景、道具、音色等资产使用 `asset`，其中音色资产的 `data` 写明 `{"kind":"voice","speaker":"<说话人>"}`；网关、生成客户端和 H3 时间线节点文件使用 `asset`，`data` 写明 `{"kind":"runtime"}` 并经审核。节点或网关文件变化会使依赖它们的所有提交失效。
- 视频生成前检查导演包、关键帧和音色：每个有台词的说话人必须有且仅有一个已审音色资产。
- 复用已有片段前，必须与当前提交记录一致并已审；旧文件存在不构成复用依据。
- 推近派生写入新的 `_dolly` 文件并登记为待审版本，不覆盖原始片段。
- 场景和全片组装只接受已审片段、已审场景及明确的剪辑决定；候选输出不覆盖旧成片。
- 关键帧图像生成本身尚未经过台账；未审核的关键帧不能进入视频生成。

## 全片阶段交接

原著来源 → 改编剧本 → 导演包 → 资产（角色多视图、场景多角度、道具、音色）→ 预演（低成本动态粗剪）→ 关键帧 → 视频 → 场景 → 全片。

- 每个阶段只消费上一阶段已审的产物；上游变化使下游失效，不影响的分支保持有效。
- 预演只验证故事因果、节奏、对白长度和转场，用于在消耗视频生成前发现问题。预演素材不得登记为正式关键帧或视频输入。
- 有台词的镜头：原生音频必须有已审的音色参考并实际挂入请求；否则改用外部配音路线，见 [audio-dubbing-post.md](audio-dubbing-post.md)。

## 失败处理

- `BLOCK`：回到责任层修复（剧本、导演、资产、提示词或关键帧），重新登记并审核，再预检。
- `REVIEW`：补充证据或独立复核。退出码、哈希一致或结构检查通过，都不能代替审核结论。
- 台账、哈希或预检输入无法读取时，按未验证处理，停止提交。

## 不能证明的内容

- 哈希、依赖与 schema 检查不证明人物、音色、空间、剧情或画面合格。
- 台账不能阻止绕过网关的直接模型调用；只有经过宿主适配器的调用受控。
- 旧文件、旧报告或同名文件存在，都不证明它们是当前版本通过审核的结果。
