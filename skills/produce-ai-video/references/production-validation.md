# 实片验证与证据分级

用于用户明确要求验证制作效果，或对本包的生产能力作声明。技能维护、运行测试和要求补齐流程本身不授权生图、视频、配音、费用或上传。所有用例正文与提示词须由 Agent 逐项创作，禁止脚本批量套模板；脚本只能核验记录与实际文件。

## 1. 验证层级

分别记录 `structural_tests`、`text_review`、`media_execution`、`full_playback_review`、`user_acceptance`，每项只用实际证据，不从上一层推导下一层。未执行标 `not_performed`，有已知问题标 `known_issues`，没有文件/播放/权限标 `blocked` 并说明缺口。不得把新合同、单帧、静态拼接或一个成功样例说成稳定完成整季。

## 2. 必需任务组

| 用例 | 必须观察的结果 | 不能替代的证据 |
|---|---|---|
| 完整对白场景 | 两至三人有行动、倾听、反应与策略变化，台词与实际语音可核对，切镜或长镜服务同一场戏 | 实际场景视频、逐句语音核对、正常速度回放与修订记录 |
| 完整短片 | 跨场因果、人物变化、剪辑、声场和结尾兑现，不读提示词也能复述 | 完整最终渲染、观众遍与质检遍、首个失信点和返工后复看 |
| 连续多集 | 至少三个连续集中的身份、状态、道具、角色知情及伏笔可信延续；有意变化有依据 | 已审集版本、跨集实际素材对照、结构检查及整段观看 |
| 改稿与返工 | 一个已批准上游变更正确影响下游，未涉及的有效内容保持不变 | 前后指纹/依赖、失效与恢复范围、真实改动素材和复看 |

用例时长、题材与目标由当前项目及预算确定，不强设镜数或高潮配额。覆盖静止/无对白、群像、物件接触、叙事时间跳转等真实风险；不为测试强行把这些全部塞入一部作品。三种连续集测试不等于长剧稳定性证明；对长片或整季的声明必须另有对应长度的完整证据。

## 3. 执行前

确定本轮项目、原文、批准资产、目标规格、用例边界、媒体/费用/上传授权、工具与播放能力、实际复核者及授权。记录软件/模型版本和可公开范围；私人素材与授权证据不因测试进入公开仓库。

缺任一前置则停在相应层，列待补项目，不虚构视频路径、复核者、试读或接受记录。现有历史媒体只证明原记录的任务和版本，不自动用于新版本通过。可先对历史授权样例做机械检查，但结果不升级其审美/用户接受状态。

## 4. 执行与验收

保存完整尝试账：用例、源/资产/提示词版本、实际提交及返回、成功/失败/未知、估计与实际费用、返工原因和次数。保留失败样本的诊断记录，不仅挑最好的一条；未授权不得额外消耗额度。

看片时执行者/复核者声明是否独立；观众遍不看作者说明，复述发生了什么、人物想做什么、何时失去信任；质检遍定位时间码、严重度、责任层和修订目标。授权内修复后重看实际最终文件，不能以抽帧代替正常速度播放，也不能用自动评分补上缺失观看。

每个结果绑定最终文件哈希、播放范围、机械报告、具体发现、残留问题与真实用户决定。用户接受一条镜头不表示接受全片/整套Skill；三个不同真实任务的接受也只支持已覆盖范围，不承诺跨模型、跨题材稳定成功。

## 5. 交付状态

报告先列实际已完成与被阻断范围，再列依据及下一步。`REVIEW_REQUIRED` 和结构检查通过不是实片通过；缺完整播放或必检证据必须保留待验证。不能将“补齐了验证合同”写成“已完成实片验证”。
