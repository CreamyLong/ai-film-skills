# 阶段审查合同

## 适用条件

用户要求"审稿/检查剧本/核对改编忠实度/检查分镜或提示词/项目校准"，或任一阶段产物需要独立审查时读取。本合同只产生审查结论与修订要求，不代替负责阶段修改来源文件。

## 审改分离纪律

- 审查输出三件：发现（编号）、影响、必须达到的修订结果与归属阶段。修改交回对应阶段执行（诊断→导演层、镜头→分镜层、映射→编译层、素材→生成层）。
- 优先由未参与当前版本创作的读者执行；条件不允许时自检，并在报告首行声明 `SELF-AUDIT ONLY`。审查者标签是披露，不是身份认证。
- 审查期间目标文件被改动：重读该目标后再记结论；不递归作废无关发现。

## 发现格式

每条发现固定字段：

```
[Blocker|Major|Minor] REV-<编号> · <一句话标题>
- 位置：<文件/场景或节点 ID/行号>
- 证据：<短引文或数据，不贴长文件>
- 影响：<观众/生产端会看到什么>
- 修订结果：<必须达到的可验收状态，不指定实现细节>
- 归属：<负责阶段>
```

结论分级：`PASS`（无 Blocker/Major）/ `REVISE`（有 Major，可局部修）/ `BLOCK`（有 Blocker，下游停）。复核方式随结论注明。

## 规则分类（只有前两类可阻断）

- `structural_invariant`：可机械校验的完整性（ID 缺失重复、时长与声明不符、参考与保留标记矛盾、画面文字与文字政策冲突）。可硬拦。
- `reviewed_invariant`：需引用证据的语义完整性（改编事实冲突、因果断链、动机反转）。拦，但必须带证据。
- `craft_default`：推荐方法，写明理由即可偏离。不拦。
- `taste_option`：创作者选择。只记备注，永不阻断。替代偏好除非违反已接受约束，否则不得升级为发现。

## 阶段审查表

### 1. 原著分析与改编忠实度（改编项目必查）

逐项核对，每项给原文行号或短引文；核不了的标 `UNVERIFIED`，不当事实用：

- **人物**：姓名、身份、动机、人物关系与原著一致；改名/合并须列出并给理由。
- **主线因果**：每个关键转折在原著有对应事件或明示改编（`ADAPTATION-CHANGE`）；方向性反转（保护↔陷害、豁免↔匹配、自杀↔他杀、真凶身份）属 Blocker 级。
- **世界机制**：装置/制度/术语的定义与功能方向不得颠倒；新造机制须标注并检查与原著机制是否冲突。
- **时间线与结局**：人物命运落点、事件先后、结尾状态。
- **主题内核**：删除风格词后，成片仍能还原原著的核心追问。

### 2. 故事与剧本

最早断链优先：因果缺环、动机不可信、无铺垫的解法、信息只靠口头断言不靠事件、对白替观众总结主题、结局收得过于整齐暴露机制。局部检查开场/中段/结尾，不要求固定节拍数。

### 3. 资产与提示词

身份变体连续、参考职责（空间/美术/风格）不混用、未见区域不冒称已知、锁定词与生成输入一致。

### 4. 分镜与关键帧

原文落实核对：剧本已锁定的动作、台词、调度、光位是否逐镜存在；切点是否改变观众可理解的信息；首尾帧状态能否交接。

### 5. 视频提示词

目标模型的合同（如原生音视频单块格式）逐条过：台词入块、声音字段、负面转正向、锚点不重复、时长与画幅在模型物理上限内。

### 6. 制作输出

媒体级缺陷走成片验收门；本表只核对"提示词承诺 vs 画面交付"的映射失败。

## 项目校准

反复出现同类发现、或审查结论与实际观感持续背离时：定位重复机制的确切位置与成因，输出规则级修订（改哪个阶段的哪条合同），不贴"AI味"标签，不为凑完整扩写范围。
