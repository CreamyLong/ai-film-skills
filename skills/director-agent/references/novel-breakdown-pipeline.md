# 原著拆解管道

## 适用条件

用户给出合法持有的小说/长篇/连载原文，要求在写剧本之前先做可追溯的结构化分析（"拆这本书""分析原著""这本书值不值得改""先看看能不能改短剧"）时读取。本管道只做只读分析：不写剧本、不建资产、不生成媒体、不批准自己的产物。

## 工作区与产物边界

- 原文输入目录**只读**，本管道不改写它。
- 全部产出落 `.project-assets/source-analysis/`：
  `_index.json`、`_progress.md`、`triage.md`、`chapters/ch-<N>-extract.md`、`story-units.md`、`rhythm-and-emotion.md`、`characters.md`、`world.md`、`adaptation-value.md`、`episode-candidates.jsonl`。
- `_work/` 是候选工作区：所有阶段先写 `_work/`，通过本阶段机械自检后再原子替换到正式路径；不要用半成品覆盖正式文件，`_work/` 不进入交付。
- 已有部分分析时读 `_progress.md` 从断点续跑，不重跑已完成阶段。

## 管道总览

| 阶段 | 做什么 | 产出 | 停靠 |
|---|---|---|---|
| S0 | 建章节索引（脚本） | `_index.json`、`_progress.md` | 索引有问题就停 |
| S1 | 改编价值快评（抽样） | `triage.md` | **停靠问创作者** |
| S2 | 逐章功能提取 | `chapters/ch-<N>-extract.md` | 覆盖率不足就停 |
| S3 | 剧情单元与节奏聚合 | `story-units.md`、`rhythm-and-emotion.md` | 阈值不达标就复核 |
| S4 | 人物归并与设定 | `characters.md`、`world.md` | — |
| S5 | 改编价值与分集候选 | `adaptation-value.md`、`episode-candidates.jsonl` | 交接剧本阶段 |

### S0 章节索引

各阶段共用同一份索引边界，不各自重新切片：

```bash
python3 scripts/novel_index.py index <原文.txt> --out .project-assets/source-analysis/_work/_index.next.json
python3 scripts/novel_index.py verify <_index.next.json> <原文.txt>
```

脚本识别"第N章/回/节"（阿拉伯与中文数字，含千/两），只认出现最多的那一种编号单位（其余记入 `ignored_heading_units`），只把短的独立行当标题（以章号开头的正文段落记入 `long_heading_lines_skipped`），剔除开头目录块，按卷校验编号。它不做编辑判断。

- `problems` 非空就停下报告，不带错表进 S1。常见四种：跳号、同卷重号、正文极少的章（多为目录残留）、章号无法解析。
- 确认 `chapter_unit` 与忽略计数符合该书实际分章方式；`long_heading_lines_skipped` 明显偏大时需与创作者确认。
- **原文没有可识别标题时索引返回空表**（例如译本用独立数字行、分隔符或纯空行分章）：与创作者确认按什么切分，把边界手写成带 `sequence`/`line_start`/`line_end` 的行，通过 `verify` 逐行检查后再发布。
- 改了原文必须重建索引；`verify` 能报出插行删行，但同行数原地改写要靠改动者自觉重建。

### S1 改编价值快评

回答"这本书值不值得花全量拆解的成本"。用脚本抽样（确定、可复现、首尾必取）：

```bash
python3 scripts/novel_index.py sample <_index.json> --count 12
```

`triage.md` 覆盖六件事：故事框架、可直接拍/需换载体/纯文字快感的比例、开篇替换点、制作负担量级、最大的三处改编风险、分集候选量级。第一行写脚本返回的 `coverage_ratio`，所有结论限于抽样范围。

**这里停靠问创作者**：给出快评与全量拆解的预计规模（依章数粗估），问是否继续。创作者明确说"一次跑完"时仍写 `triage.md` 但不停下——它是 S5 要回填对照的第一版假设。停靠时把 `_progress.md` 状态写成 `stopped_after_triage`。

### S2 逐章功能提取

每章提取戏剧功能：各段如何改变角色的选择、信息、权力或关系，落 `chapters/ch-<N>-extract.md`；`<N>` 用索引 `sequence`，不用原文章号（多卷书章号会重复）。能并发就分批并发（每批 5–8 章），否则串行，两条路径写法与自检相同。

全部落盘后跑覆盖率：

```bash
python3 scripts/novel_index.py coverage <_index.json> <chapters目录>
```

先更正 `unmatched_files` 的命名，再补真正缺失的章；**覆盖率不足不进入 S3**。单章连续失败两次先记入 `_progress.md` 继续其他章，S2 结束补齐；仍有缺章就停在 S2 报告缺失范围，不做全量聚合。

### S3 剧情单元与节奏

从逐章提取聚合；事实不清时按 span 定点回查原文，不重新通读全书。先识别故事框架（框架决定按什么切单元），再产出：

- `story-units.md`：有始有终的单元，每个记录进入状态、冲突、代价、出去状态；
- `rhythm-and-emotion.md`：关键信息如何逐章推进、情绪触动点的铺垫→释放→余波、跨章伏笔与兑现、依观众收益排名的爽点表。

聚合后做三条阈值自检（归属置信、覆盖率、重叠率）。阈值是复核信号：重叠率偏高先区分多线交叉与边界重叠，再决定是否合并。

### S4 人物与设定

归并人物（跨章去重、别名归一、分级），从提及数据归纳世界规则与势力。专名、绰号、"姓氏+头衔"只有在同指证据充分时才合并；泛指的外貌称谓或职务不触发合并。

**人物条目是候选，不是资产**：带 `unresolved` 与来源引用即可。真正的资产身份只能在改编决定落进已接受剧本之后建立，绕过这条链等于让原著人物表冒充剧本出现证据。

### S5 改编价值与分集候选

- `adaptation-value.md`：哪些单元在目标载体里能直接成立、哪些要换载体、哪些是画面上无法兑现的纯文字快感（内心戏、叙述性诡计、长铺垫）；制作负担落在哪里。开头**回填快评**：把 S1 中被全量结果推翻的判断及原因写明。
- `episode-candidates.jsonl`：依爽点分布、局部戏剧结果与精确交接切候选集，不依章号或字数平均切；每条带来源 span、承担的功能、承接的爽点与未决项。

### 交接与忠实度衔接

S5 完成后向创作者汇报：拆了多少章、跳过哪些、分了多少候选集、最大三处改编风险、快评里被推翻的判断。候选交给剧本阶段做改编决定；进入制作后，改编忠实度按审查合同的改编忠实度核对表逐条回查——剧本与分镜必须能追溯到本管道的 span 与单元，对不上就是发现，不是创作自由。

## 硬规则

- 不把原文成段复制进分析产物：记录 locator/span 与去引用的功能摘要，需要证据时引用最短必要片段。
- 不用固定章数配方、情节点数量或篇幅比例替代因果判断。
- 只有可机械校验的完整性（索引/span 可证明性、引用完整性、覆盖率）与语义忠实义务能阻断；"从哪里开篇、保留哪条线"是创作者的 taste 选项，不得单独阻断。
- 个别片段无法处理时跳过并记录，不中止整章整本——中止会让下游拿到有洞却看不出洞在哪的分析。
- 需要质量结论时交给独立审查（阶段审查合同），本管道不自批。
