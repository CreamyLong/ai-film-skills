# 硬绕审查：权限、时机、代价、反制、知情、证据链

用于诊断“剧情不是复杂，而是靠编剧硬推”的段落。它只找结构问题，不代写剧情、不改台词、不替作者选择方案。适用于分集地图、单集大纲、剧本和关键转折审稿。

方法综合自公开 skill 的审查思路：`jtydhr88/screenwriting-skills` 的系列引擎四问、`sw-story-structure` 的巧合规则、`zenstory-ai/drama-skills` 的 `SCR-02`/`STY-09` 与反套路条目、`zhlmi/screenplay-review-checklist` 的 B-01/C-01/C-02；证据链与删掉测试按本项目生产需要补充。以下文字为本包重写，不复制原文。

## 1. 八个问题

每个重大转折、破局、反转、证据出现、人物到场，都逐项回答：

| # | 问题 | 合格回答 | 不合格信号 |
|---|---|---|---|
| 1 | **授权/进入**：谁有合法或物理权限做这件事？ | 职务、钥匙、门禁、内部人、伪造文件、暴力突破，且前文有依据 | “因为剧情需要他进去”；角色突然拥有未建立的权限 |
| 2 | **时机**：为什么是现在，不是七年前或下一集？ | 触发事件、代价变化、对手行动、最后期限 | 没有触发点；早就可以做却一直不做；拖延只为凑集数 |
| 3 | **代价**：他付出了什么，失去什么？ | 不可逆的失去：身份、关系、权限、安全、道德位置 | 零成本推进；做完没有任何后果；下一集恢复原状 |
| 4 | **反制**：对手为什么没拦住？ | 对手有误判、资源限制、信息差、内部牵制，且前文建立 | 对手突然降智；反派只在主角需要时出现；无人防守关键位置 |
| 5 | **知情**：谁在什么时候知道什么，怎么知道的？ | 亲见、转述、文件、监控、推断，来源可追溯 | 角色使用自己不可能知道的信息；观众知道但角色无理由知道 |
| 6 | **证据链**：这东西在法庭、平台或现实规则里站得住吗？ | 来源、保管、鉴定、程序、可复核性成立；脏证据只作线索 | 只靠“看起来像证据”；非法取证却直接定罪；关键结论无独立来源 |
| 7 | **巧合方向**：这个巧合是制造问题，还是解决问题？ | 巧合把人物推进困境；解决靠人物选择与已埋伏笔 | 巧合在结尾解围；关键证据恰好送到；反派恰好自曝 |
| 8 | **删掉测试**：删掉这一步，后面哪一拍会塌？ | 能指出具体依赖；或删掉后确认是可选装饰 | 删掉毫无影响＝注水；删掉全塌但前面没有铺垫＝承重墙悬空 |

## 2. 判定

- **blocker**：第 1、5、6 问只能靠“剧情需要”回答，或第 7 问是巧合解围。故事当前不成立，停止进入分镜/生成。
- **major**：第 2、3、4 问缺一项，导致转折像硬推；回到分集或场景层补因果。
- **minor**：第 8 问显示某拍可删或可并；按经济性处理，不升格为剧情硬伤。

不要用“他就是这样的人”“观众不会注意”“后面会解释”放行。后面要解释的，现在就要有可指出的依据。

## 3. 审稿输出

```markdown
# 硬绕审查：<集/段>

## blocker
- **转折**：<具体场次/动作>
  - 缺哪问：<授权/知情/证据链/巧合方向>
  - 证据：<原文行号或实际画面>
  - 为什么现在不成立：
  - 修复方向：<补权限/补触发/补代价/换破局方式/降级为线索>

## major
- ...

## minor
- ...

## 已通过
- <哪几问有明确依据>
```

每条必须指到具体场次、动作或台词；禁止“逻辑不够严密”这类空话。只给方向，不代写整场。

## 4. 常见硬绕与替代方向

| 硬绕 | 替代 |
|---|---|
| 主角突然能进警队/证物室/对手老巢 | 先建立内部人、伪造权限、调虎离山或暴力突破的代价 |
| 关键证据恰好被寄到/拍到/捡到 | 让证据由对手的行动产生，或由主角用已建立的手段取得 |
| 反派在结尾突然自曝 | 让自曝成为交易、挑衅、误判或证据逼供的结果，并付出代价 |
| 角色知道不该知道的事 | 补亲见/转述/文件来源；或让他不知道，用错误判断推动 |
| 非法取得的证据直接定罪 | 增加独立可采信证据；脏证据只用于找方向，不用于定案 |
| 七年前早就能做的事拖到现在 | 补“为什么当年做不到”：权限、恐惧、被监控、家人安全、制度堵死 |
| 反转没有前文事实 | 回到前文埋伏笔；不能靠反转时补解释 |

## 5. 与工作流的衔接

1. **分集地图阶段**：对每个回合的破局、反转、证据出现跑八问；blocker 不进写作。只对**剧本原文**提问，不对分集梗概/故事引擎的转述提问——梗概会丢掉已存在的铺垫（实测案例 §5b）。
2. **单集剧本阶段**：对每个关键转折跑八问；缺依据回开发/分集层补，不在台词里解释。
3. **分镜/生成前**：把已通过的权限、知情、证据链写进镜头 entry/exit state；生成后按实际画面复核。
4. **审稿对话**：作者能指出前文依据时撤销误判；不能用“这是风格”绕过结构问题。

## 5b. 实测案例：EP014「幕后合伙人」周启明现身（2026-11-20 回溯，两次修正）

对 faked-death-case EP014 的关键转折「周启明现身仓库」跑八问。教训先说：**必须读剧本原文，不能只读分集梗概**——第一次回溯只看 series-map 的一句话，误判了两个问题；读完剧本后八问实际判定如下：

| 问 | 判定 | 依据（剧本原文） |
|---|---|---|
| 权威/能力 | 通过 | 七年前喂假证据给韩峥（EP013 揭示） |
| 时机 | **major → 已缝合** | 诱饵=冷库下的尸体（SC001"仓库下面有尸体"）成立，但缺"为什么他必须今晚亲自来"；2026-11-20 补：韩峥经邱建民放话"搜查令明早批、冷库今晚封存"，尸体必须在他眼皮底下转移，不敢交给别人也不敢再等 |
| 成本/收益 | 通过（缝合后） | 带两人赴约=傲慢+杀人证据不敢假手；成本由时限压力解释 |
| 对抗/反制 | 通过 | 警笛、使眼色、反威胁沈远，双向设局 |
| 知识 | **通过** | SC004 周自述参与假死布置："是他自己要死。我只是帮他选了个地方。"——知情有原文依据 |
| 证据链 | 通过 | 录音成为 EP016 反杀材料 |
| 巧合方向 | 通过 | 无巧合 |
| 删除测试 | 通过 | 删掉本集，EP015/016 动机断裂 |

结论：EP014 剧本**基本成立**，只需一句时限缝合（已补）+ 周启明出镜镜头的身份资产一致性修复；不需要整集重制，也不需要"EP013 末放风"这类额外铺垫（第一版回溯的建议作废）。

上游缺口仍然存在：**story-engine 原本没有周启明的行动模型**——这是设定总表层的问题，不是 EP014 的问题。此类空洞由 `scripts/story_bible_check.py`（故事设定总表检查）在分集写作前拦截。

## 6. 边界

- 不评价题材、价值观或内容合规。
- 不替作者决定“应该怎么改”，只给修复方向。
- 不把“复杂”本身当缺陷；只审每个转折是否有可指出的依据。
- 不保证通过本审查的故事一定好看；它只排除已知的硬绕。
