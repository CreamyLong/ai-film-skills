# 长篇交付档与三段门槛

平台投稿标准会变，且不同平台的规模、格式和题材偏好并不相同。本文只提供**可配置的交付档 + 三段验收门槛 + 分众选题顺序**，不把任何单一平台文档当成创作法则。数字是默认示例，落项目时以当前平台文档为准，并把最终取值写进 `项目开发/project.json`。

## 1. 交付档：先量规模，再谈结构

长篇投稿通常先被规模卡一次：集数与总字数不达标，结构再好也进不了评估。把规模当**项目参数**，不要凭感觉估算。

`项目开发/project.json` 建议增加（字段名可随项目既有 schema 调整）：

```json
{
  "platform_profile": {
    "source": "当前投稿平台的公开要求（记录日期与链接）",
    "min_episodes": 70,
    "min_total_words": 70000,
    "typical_episode_words": 1000,
    "format_template": "平台统一剧本模板的名称或路径",
    "series_listing": "连载 / 系列 / 完结单次上传"
  }
}
```

使用规则：

- 集数与字数是**下限**，不是目标；不要用灌水凑字数，字数不足时先补功能场次，不是拉长对白。
- 交付前用分集地图行数 × 每集字数估算总规模，达不到就在交接时明确写「未达投稿规模：差 N 集 / 约 M 字」，不静默交付。
- 连载项目必须标明首发集数与更新安排；系列剧标明各季边界。
- 平台模板是格式契约：场景、对白、`[OS]`、画面描述都要按模板字段填满，缺字段等同未交付。

## 2. 三段门槛

按「首集留人 → 前 3 集追更 → 全剧可追完」验收。三段各自独立，前一段不过，不要靠后一段补救。

### G1 首集：留下来

可观测判据：

- 第 1 集内出现核心吸睛点：核心冲突、危机、暧昧、反差或悬念至少落地一个，且不是靠旁白宣布。
- 男频向项目，首个吸睛点落在首场次；女频向项目，首集内必须明确。
- 开场 10 秒内不出现世界观长解释、无冲突寒暄、家庭背景铺陈。
- 观众看完首集能回答三件事：主角是谁、被什么压迫、接下来要解决什么。
- 每场都有功能（推进主线 / 揭示关系 / 制造冲突 / 强化人设），没有纯过渡场。

不过时的修法：把后文高光前置，重排开场，删掉无功能场次；不要靠加旁白解释。

### G2 前 3 集：追下去

可观测判据：

- 第 2、3 集各有独立的当集结果，不是首集的延长解释。
- 每集都有新的信息或新的阻力，连续三集不出现「目标、处境、关系」零变化。
- 集尾留下具体决定、危险或问题，且下一集确实承接。
- 主角的选择开始暴露性格底色，行为可被前史与处境解释。

不过时的修法：先修当集结果与集间交接，再调节奏；不要用打脸或升级硬顶。

### G3 全剧：追得完、续得动

可观测判据：

- 主线可支撑目标集数：每个阶段改变权力、信息、关系、暴露、资源、时间或代价之一。
- 强情绪点有分布：按项目节奏档案至少每 10 集兑现一个，且都有前置铺垫。
- 支线反哺主线；删掉任何一集都能说清损失了什么状态台阶，否则该集没有存在理由。
- 前后设定、人物状态、能力规则可回查，关键反转均有前置信息。
- 结局收束主线，或明确停在可续的卡点；不允许突然完结或仓促烂尾。

## 3. 先人群、再题材、后爽点

选题顺序颠倒，最容易写出「热门元素拼盘」：说不清给谁看，只能靠堆梗。

1. **定目标人群**：偏青年女性 / 偏青中年女性 / 偏中老年女性 / 男性向 / 男女均可但需明确爽点归属。写进创作简报的「目标观众」。
2. **定题材方向**：按人群选择熟悉的爽感框架（成长、职业婚恋、家庭关系、玄幻历史、悬疑民俗、游戏末日科幻、强视觉角色等），再从题材卡取该题材的压力来源、场面细节与制作负担。
3. **定新鲜变量**：在熟悉框架上只加**一个**能被一眼感知的新变量，并让它成为核心内容，而不是提一次就消失的装饰。
4. **校验**：若换个题材名也成立，说明还没选定人群；若去掉新变量完全不影响剧情，说明变量是装饰。

常见平台方向可作参考，但不要机械拼接；一个项目只服务一个主要人群。

## 4. 改编反模式清单

以下症状来自被拒稿剧本的共性，按「表现 → 判据 → 改法」检查。结构性条目在 [adaptation-craft.md](adaptation-craft.md) 已有方法，这里只列可快速自查的失败模式。

| # | 表现 | 判据 | 改法 |
|---|---|---|---|
| 1 | 流水账照搬，开场无戏 | 前 2 集按原文章节顺序走，冲突迟迟不出现 | 提取核心冲突重构开场，高光前置 |
| 2 | 只转格式，不做戏剧化 | 大段心理、抒情、全知叙述无法画面化 | 以「场」重写，把心理外化为动作与短台词 |
| 3 | 场面很大，细节是空的 | 只有「天地变色」级描述，无具体动作与反应 | 落到谁的手在抖、哪件东西先碎、旁人什么反应 |
| 4 | 关键信息丢失，前后对不上 | 能力、反转、身份凭空出现 | 列「不可删信息」清单，维护设定与状态表 |
| 5 | 人设割裂，行为不成立 | 同一人物前后判断标准漂移，选择无动机 | 先定身份、目标、底线、说话方式，再写选择 |
| 6 | 情绪链路被截断 | 只虐不爽、只铺不收，反击无反应 | 每段情绪有铺垫与明确落脚点 |
| 7 | 设定轰炸或一刀删除 | 开篇罗列等级与势力；或关键规则完全不交代 | 用事件演规则，复杂设定精炼而非删除 |
| 8 | 视角漂移，旁白泛滥 | 频繁切配角/反派，靠旁白讲心理 | 事件收束回主角，删上帝视角旁白 |
| 9 | 不做减法，平均用力 | 平淡过场占大篇幅，连续多集状态不变 | 先删线再合并，篇幅向强冲突集中 |
| 10 | 前精后跑，中后段崩塌 | 前几集手写、后面批量生成，设定开始矛盾 | 先完成全剧与分集卡，再写正文 |
| 11 | 魔改原著，逻辑割裂 | 核心人设、动机、主线被替换 | 重构只服务戏剧化，不换核心设定与情绪 |
| 12 | 车轱辘话与模板痕迹 | 同一意思换说法反复讲，角色来回表态 | 一个信息只讲一次，逐集人工校对 |

AI 洗稿的典型症状单独记：前后对白承接不上、凭空捏造前文没发生的对话、人物说话一个口吻、只推进打脸升级而事件之间没有因果。出现任一症状，退回分集地图检查因果，不要在原稿上继续润色。
