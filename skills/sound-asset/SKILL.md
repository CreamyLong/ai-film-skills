# 声音资产参考样音生成预设

> 当前包已经包含全部运行规则、参数依据和质量门；不使用未经权利人与用户确认的真人声音、声纹或录音。

## 提示词逐项创作硬规则

- 禁止编写或运行批量生成提示词的脚本，包括 Python/Shell/JS、循环套模板、变量替换、片段拼接、批量调用模型或其他自动化流程。音色描述、试音文本、演绎指令、音效与音乐提示词及其排除项均适用；用户要求多条或全片提示词也不构成例外。
- 必须依据当前剧本、已定设计与每个资产/说话人的具体关系，逐项理解、逐项撰写、逐项复核完整正文。模板仅供组织表达；“编译”指逐项转写已定决定，不授权程序代写。
- 脚本仅可校验、编号、索引、计算哈希、原样保存或封装已经逐项完成并复核的完整正文；不得生成、补写、改写或拼装提示词正文。已授权的样音/配音批量执行仍须使用这些完成稿并通过相应质量门。
- 不能以逐条循环、拆成多个单次脚本、改称编译器或先批量生成再人工润色绕过。发现脚本批量产出的提示词时，不得交付或提交生成，须回到源材料逐项重新撰写和复核。

## 0. 加载规则与映射表

先确定本次资产类别与改动范围。首次建立或重设计按下方剧本依据、描述、状态、样音组和适用模板完成；局部修改只执行受影响部分，编号/文件查询直接回答。同一上下文已完整读取且未变的材料复用，不为改一处重新跑全流程。已确认编号不得复用。

| 类别 | 编号 | 锁定的是什么 | 不属于本资产 |
|---|---|---|---|
| 角色音色 | V01–V99 | 一个说话人的声音身份：声源、音域、音质、口音与发声习惯 | 某一句台词的情绪、节奏和内容 |
| 环境声底 | A01–A99 | 一个空间在某种运行状态下的连续底声 | 推动剧情的单次声音事件 |
| 标志音效 | X01–X99 | 反复出现、观众需要认出的同一个声音 | 一次性动作拟音 |
| 音乐主题 | M01–M99 | 可辨认的动机、配器、速度与调性范围 | 某一场的具体配乐剪辑与进出点 |

| 节 | 独立输出 | 用途 |
|---|---|---|
| 1–5 | 资产描述、锁定规则 | 确定声音身份与状态 |
| 6–7 | 路线适配与任务/提示词字段 | 直接生成或录制参考样音 |
| 8–9 | 验收和防崩 | 独立质量检查 |
| 10 | JSON 合同 | 供后续制作直接读取 |
| 11 | 类型适配字段 | 注入配音、原生音视频提示词或混音任务的对应段落 |

### 剧本先行与设计依据

首次建立或重新设定资产且用户提供剧本时，通读所提供的完整正文，理解人物关系、身份、年龄、地域、身体状态和时间线，再回到该声音出现的场次设计。局部修订复用本轮已读且未变的依据，只补读受影响原文与必要前后状态。不能只搜角色名或读摘要就声称通读；只有片段时说明覆盖范围，未给剧本时依据当前描述设计。

内部保留简短设计依据：正文来源与阅读范围、相关场次、已确认事实、设计推定、关键未知。设计要能解释“为什么这个人在此时听起来是这样”；后文的衰老、受伤、变声或身份揭示不能提前带入当前场次。

未提供声音细节时，从剧本主动提出合理设计；影响身份揭示、既有锁定事实或权利的关键未知才需确认。一般的音域、语速习惯、口音浓淡可作有依据的设计推定，不一律退回待确认；推定不能冒充原文或用户已确认事实。

### 交付模式

按用户点名的结果选择，不自动扩展为整套：

- **设计说明/样音任务**：交付当前请求的音色设计、试音文本、演绎基线与资产合同；尚未生成的样音用空列表并标为计划，不填写虚构文件路径或声称已审听。
- **实际样音**：用户要求出声、有可用能力且权利与花费已获授权时生成或整理所需样音；点名一条先交一条。实际听过后记录检查结果，用户批准前保持 pending_review。
- **诊断/局部修改**：围绕给定音频或设定指出可听问题、原因假设和对应修正；保留未点名的身份与状态，不默认重做全部角色。

新建音色、换声源或整体重选角时读取 [选角与试音方法](references/voice-casting-and-audition.md)；环境声底、标志音效或音乐主题读取 [环境声、音效与音乐主题资产](references/ambience-sfx-music-assets.md)。已有明确声源只做局部派生时直接继承基准，不重开选角。

### 权利与授权门

设计文本不需要授权；以下动作各自需要明确授权，前一项通过不延伸到后一项：使用真人录音作参考、声音克隆、上传音频到外部服务、付费生成、商业交付。真人声音记录权利人、授权范围与证据位置；公开可下载不等于可克隆或可商用。权利不明时可以继续不依赖它的设计，并改提预设音色或文字描述音色等替代路线，不得据此上传、克隆或交付。

## 1. 描述维度表

按类别取适用项，不为填满字段编造。

| 类别 | 维度 |
|---|---|
| 角色音色 | 说话人与别名、年龄感与性别感、音域与常用音高区、音质（明/暗、厚/薄、气声、鼻音、沙哑）、共鸣位置、语言/方言/口音浓淡、咬字与语速习惯、句尾处理、呼吸与气口习惯、身体状态、社会身份带来的说话方式、与同场角色的区分点 |
| 环境声底 | 空间体积与表面、持续声源及远近层次、运行状态（营业/深夜/停电）、时段与天气、听点位置、可循环性、不得出现的可辨识事件 |
| 标志音效 | 声源物与材质、触发动作、起音/持续/衰减形态、频段重心、空间与距离基准、叙事作用、允许的变化范围 |
| 音乐主题 | 叙事功能、所属人物/关系/地点、动机轮廓、调式与调性范围、速度范围、配器、织体密度、有无人声、与对白共存方式 |

规则：区分剧本事实、设计推定与关键未知；只把用户或剧本已确认的维度写入 locked_features，待审设计不冒充已锁定。用可听的具体特征描述，“有磁性、高级、好听”不能替代音域、音质和说话方式。

**音色身份与表演分开。** 音色资产回答“谁在说”，逐句演绎回答“这一句怎么说”。愤怒、哭腔、低语是同一音色的表演，不建新资产；音色参考不自动规定任何一句的内容、情绪或节奏。

## 2. 一致性/状态规则

- 一个说话人在同一部作品里只有一个已审音色源；换源等于换人，需要用户重新批准并列出受影响的既有配音。
- 同一人的多个称呼先归一到一个编号。别名、称谓、画外音标记不一致会让后续逐句映射漏掉台词；合同的 `speaker_aliases` 必须列全剧本中实际出现的写法。
- 两个角色被设定为同一副嗓子（伪装、双重身份）时共用一个音色源，差异只放在演绎基线里。
- 变体使用原编号后缀（如 V01b）并记录原因：年龄段、不可逆的嗓音损伤、变声、长期病弱。电话、隔门、广播等传输效果是后期处理，不是变体；疲劳、伤势与情绪余波按故事时间写入状态合同。
- 环境声底的变体对应空间运行状态（A01 营业、A01b 打烊）；标志音效保持同一声源身份，距离与空间差异由混音处理；音乐主题的变奏记录保留了哪些可辨认要素。
- 样音一经用户审听批准，后续制作只可引用，不能重新发明声音；不得悄然覆盖已审版本。

## 3. 参考样音组

样音组的作用相当于人物的多视图：让一个声音在不同使用条件下都有可核对的基准。新建角色音色时默认规划下列四条，用户只要一条或点名范围时严格遵从：

| 样音 | 回答什么 |
|---|---|
| 中性基准 | 平静陈述时的音高、音质、语速与口音；作为身份比对的主参考 |
| 力度上限 | 提高音量和情绪时是否还是同一个人，有无破音或音质突变 |
| 力度下限 | 压低、近距离或气声时身份是否保持，咬字是否仍可懂 |
| 长句连读 | 气口位置、句内节奏与句尾处理是否稳定 |

按剧情需要再加非语言声（笑、叹、喘、哭）、外语或方言句、演唱片段，不为凑数添加。试音文本从角色自己的语言习惯撰写，优先使用不含剧透的原创句；需要用剧本原句时逐字引用。每条注明对谁说、想达到什么，不只贴情绪标签。

样音是干声参考：单一说话人，无背景音乐、无环境声、无混响与效果；首尾保留自然起音与尾音。时长、采样率和格式按所选路线的真实要求与实测确定并记录实际值，不套固定秒数。

环境声底、标志音效与音乐主题的样音规划见对应参考文件。

## 4. 演绎基线

每个角色音色附一段简短的演绎基线，说明此人默认怎样说话：身份在前，习惯在后，用能改变听感的具体做法表达（“关键词前留半拍”“句尾下沉不上扬”），不堆叠音色形容词。它是后续逐句演绎的起点，不替代逐句指令；过长或互相矛盾的基线会稀释效果，按所选模型的实际响应增删。

演绎指令与实际台词分开存放和提交；指导语不得混入被念出的文本。

## 5. 技术与可听规则

- 语音样音可懂、无削波、无明显底噪、无合成伪迹（金属声、吞字、重复、拖长的异常尾音）；不含第二个人声。
- 环境声底在标称循环点衔接自然，持续声源稳定，没有会被观众认出为剧情事件的突出声音。
- 标志音效是单一、完整、首尾干净的事件；不夹带环境、音乐或人声，除非那就是它的设计。
- 音乐主题能被辨认，结尾完整或标明可剪辑点；未要求时不含人声；记录实际速度与调性。
- 记录每个文件的实际时长、采样率、声道数与内容哈希；数值来自测量，不照抄任务参数。

## 6. 路线适配

| 路线 | 合同里记录什么 | 主要风险 |
|---|---|---|
| 预设音色 | 服务/模型、预设标识、可用性核对日期 | 标识写错或下线时被静默替换为默认声音 |
| 参考音频克隆 | 参考文件、哈希、权利、克隆授权 | 参考文件丢失；长内容中音色漂移；权利缺失 |
| 文字描述生成音色 | 完整描述、种子或返回的音色标识 | 每次生成不是同一个人，必须固化返回标识或样音 |
| 原生音视频模型的音色参考 | 参考文件与其在请求中的实际职责 | 参考未真正挂入请求；模型自行念出随机声音 |
| 真人录音 | 演员、授权范围、录音条件 | 授权范围不含生成或克隆 |

任何路线都不得改变 locked_features；模型或服务能力未经本次实测时标记 unverified，不作为硬约束。选定路线后记录能复现同一声音所需的全部信息；“用了同一个预设名”只说明声源相同，不证明实际输出稳定。

## 7. 资产任务模板

以当前交付用途和设计意图起笔，再写决定身份的可听特征，最后安排样音与必要保持项。短段落或结构化写法均可，按任务复杂度组织，不固定字数；不把全部检查项贴到末尾。

### 模板A：角色音色

~~~text
[说话人自然名称与全部别名]，[年龄感/性别感/身份与当前故事时间的身体状态]。
[音域与常用音高区、音质、共鸣、口音与咬字、语速和句尾习惯；与同场哪位角色如何区分]。
[选定路线与声源标识或参考文件；权利与授权状态]。
[本次需要的样音及各自回答的问题；每条的试音文本、说话对象与目的]。
[演绎基线；必须保持的特征与针对当前问题的少量排除]。
~~~

### 模板B：环境声底

~~~text
[空间自然名称与运行状态、时段、天气]，[听点位置]。
[空间体积与表面带来的声学特征；持续声源按近/中/远分层及各自密度]。
[时长与循环要求；不得出现的可辨识事件]，无对白、无音乐。
~~~

### 模板C：标志音效

~~~text
[声音自然名称与叙事作用]，[声源物、材质与触发动作]。
[起音、持续、衰减形态与频段重心；基准距离与空间]。
[允许的变化范围；必须保持的可辨认特征]，单一事件，首尾干净。
~~~

### 模板D：音乐主题

~~~text
[主题自然名称]，[叙事功能与所属人物/关系/地点]。
[动机轮廓、调式与调性范围、速度范围、配器与织体密度]。
[时长、结尾方式或可剪辑点；有无人声；与对白共存时的避让方式]。
不指名现有作品或在世音乐人作为模仿对象。
~~~

用户可复制的任务正文使用自然名称，编号保留在后台合同。不把具体镜头的台词时间窗、口型或混音电平写入资产任务。

## 8. 质量检查清单

- [ ] 编号、版本、名称、类别和用途唯一；说话人别名已列全
- [ ] 首次设计已读提供的正文；阅读范围和设计依据可核对，没有只凭角色名套模板
- [ ] 第1节维度已区分事实、合理设计推定与关键待确认；当前状态符合剧情时间线
- [ ] 每个说话人只有一个音色源；路线、标识或参考文件、复现所需信息已记录
- [ ] 权利与各项授权状态明确；未授权动作没有被执行
- [ ] 年龄感、性别感、口音与角色设定一致
- [ ] 同场角色只凭听觉可以分开
- [ ] 样音组内各条听起来是同一个人；同一文本重复合成仍稳定
- [ ] 语音逐字念出了试音文本，没有吞字、增字或串入指导语
- [ ] 样音为干声，无第二人声、音乐、环境或效果；无削波与明显伪迹
- [ ] 环境声底可循环且无剧情事件；标志音效单一完整；音乐主题可辨认且未指名模仿
- [ ] 文件时长、采样率、声道与哈希来自实际测量
- [ ] JSON 合同可被下游解析

按交付阶段检查：设计文本只验证设计与合同，未生成或未听过的可听项目标 not_evaluated；实际样音的适用项目失败时为 rework。逐字核对可用语音识别回读辅助，身份一致可用说话人相似度测量辅助；两者都是证据而非结论，没有相应工具时如实标为未验证。只有实际样音经用户审听通过才进入 assets_approved，文本通过不替代听音。

## 9. 排除约束

三层仅作内部风险来源，最终任务只保留当前样音需要的限制；不机械叠加无关清单。

第一层（通用）：影响当前设计的削波、底噪、截断、异常静音、错误语言。
第二层（sound）：音色漂移、年龄或性别感错位、口音跑偏、吞字增字、念出指导语、多余人声、与锁定不符的混响或音乐、循环接缝、未授权的真人或作品模仿。
第三层（听感）：先按用途选择。干声参考排除空间感与效果；环境声底保留真实空间；设计上的沙哑、气声、口吃或方言属于角色特征，不当作缺陷排除。

需要诊断具体错误时再读 `references/NEGATIVE-CASE-BOOK.md`；选用相关项，不把案例或数值当作统一配方。

`sound_kind` 取 `voice`、`ambience`、`signature_sfx` 或 `music_theme`；非语音类别省略 `speaker`、`speaker_aliases`、`voice_source` 与 `performance_baseline`，在 `locked_features` 中记录该类别的锁定要素。

`audition_plan` 按需记录各样音的 `purpose`、`text`、`addressee`、`intent` 与 `reference_role`；单条请求可只有一项。未生成时只记录计划，不编造文件路径。`reference_audio` 的每项记录 `path`、`sha256`、实测 `duration_seconds`、`sample_rate`、`channels` 与它对应的样音。

后续制作若使用台账登记音色，本合同可直接映射为一条音色资产：类别 `voice` 加 `speaker`，文件哈希取自已审样音。本 Skill 自己完成审听字段、编号登记、权利记录和对照复核要求；后续制作只读取已交付的资产合同，不得重写锁定特征。

## 11. 类型适配字段

把声音资产绑定到当前分镜、配音任务或原生音视频提示词的对应内容：说话人使用自然名称，编号仅在后台合同中映射。绑定时核对三件事——逐句的说话人写法能归一到本合同、所选路线的声源或参考确实进入了实际请求、演绎指令与台词原文分开。

正式配音或带对白的视频生成前，实际样音须经用户审听进入 assets_approved；后续生成保持已批准的声音，并对照实际结果核验。尚未审听的资产保持候选，可用于标明假设的候选分镜、设计稿和文本提示词，不以缺少样音或人审为由拒交所请求的文本；这些文本不提升资产批准状态，也不授权直接进入正式生成、克隆或上传。
