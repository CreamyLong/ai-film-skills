# Omni 成片审判员

把一个可接收图片、视频、音频、文本的多模态模型当作**第二双眼睛**：它指出证据，人做判决。它的输出永远不是“通过”，而是“在几分几秒发现了什么”。

## 提示词逐项创作硬规则

- 禁止编写或运行批量生成提示词的脚本，包括 Python/Shell/JS、循环套模板、变量替换、片段拼接、批量调用模型或其他自动化流程。审查问题、证据描述与结论摘要均适用；用户要求批量审片也不构成例外。
- 必须依据当前产物、镜头与人物关系，逐项理解、逐项撰写、逐项复核完整审查问题。模板仅供组织表达，不授权程序代写。
- 脚本仅可校验、编号、索引、计算哈希、原样保存或封装已经逐项完成并复核的完整审查问题；不得生成、补写、改写或拼装提示词正文。
- 不能以逐条循环、拆成多个单次脚本、改称审判器或先批量生成再人工润色绕过。发现脚本批量产出的审查问题时，不得交付或提交生成，也不得作为验收依据，须回到具体帧或秒逐条重新核对。
- 本 Skill 不生成、不改写、不拼装任何创作提示词；审查结论必须能落到具体帧或秒。

## 1. 先定角色

- 本 Skill 只做**渲后审查**：检查真实文件，不生成、不重写、不混音、不改分镜。
- 它不能证明“好看”“表演成立”“剧本因果成立”；这些回到导演/编剧审查。
- 所有结论必须能落到**帧号或秒数 + 可见/可听证据**；落不到的不采信。
- 默认输出 `review_required`。只有人看过那一帧、听过那一秒，才允许改 `reviewed`。

## 2. 输入

| 输入 | 必需 | 说明 |
|---|---|---|
| 成片或单镜文件 | 是 | 真实交付文件，不用代理片、静帧或工程文件代替 |
| 分镜/提示词/剪辑表 | 是 | 用于核对“说拍什么”与“实际生成什么” |
| 角色参考图 | 身份审查必需 | 每个说话角色一张脸锚 |
| 场景参考图 | 空间审查必需 | 每场一张环境锚 |
| 审查授权 | 上传外部模型必需 | 明确素材允许发送到该服务；敏感项目先脱敏或改用本地模型 |

没有参考图时，仍可查字幕、重影、杂音、机位和序列叙事，但**不能判身份**。

## 3. 六层审查

按成本从低到高，逐层决定是否继续：

| 层 | 看什么 | 送什么 | 判什么 |
|---|---|---|---|
| T1 身份 | 说话人是否同一人 | 角色参考脸 + 该镜单帧 | 换脸、年龄漂移、造型突变 |
| T2 文字 | 烧录字幕、伪文字、错字 | 六帧抽检图 | 字幕内容、位置、是否遮脸 |
| T3 空间 | 同场是否同一房间 | 同场 10–12 帧网格（带时间码） | 墙面、门窗、座椅、人群、光源跳变 |
| T4 声音 | 切点是否换房间 | 切点前后各 2 s，成对送 | 响度台阶、底噪断裂、鬼声、爆音 |
| T5 序列 | 观众能否看懂 | 同场 12 帧 + 人物背景 | 谁是谁、关系是否建立、流程是否清楚、有无无源特写 |
| T6 伪影 | 手指、肢体、拖影、重影、漂浮物 | 5–10 s 原片或可疑帧 | 多指、断肢、叠影、粒子、穿模 |

详细送法、提示词和采样规则见 [references/review-tiers.md](references/review-tiers.md)。

## 4. 判定规则

分三级，禁止只写“有问题”：

- **blocker**：观众会直接出戏或看不懂——换脸、烧录字幕、同场空间断裂、切点声音跳变、明显多指/断肢。
- **major**：不致命但持续削弱可信度——造型漂移、背景人群穿帮、机位与提示词矛盾、静帧无运动。
- **minor**：可留待下一版——轻微噪点、远处伪文字、非焦点区小瑕疵。

每条必须带：时间码/镜号、证据类型、模型原话摘要、修复归属层（资产/提示词/生成/剪辑/声音）。

判定与报告格式见 [references/verdict-schema.md](references/verdict-schema.md)。

## 5. 工作流

1. **收集证据**：从 editlist、prompts、成片生成网格、身份对、切点音频；可用 `scripts/episode_audit.py` 自动打包。
2. **分层送检**：先 T2/T3（便宜、覆盖广），再 T1/T4（关键镜和切点），最后 T5/T6（主 key 镜）。
3. **逐条复核**：人打开对应帧/秒确认；模型说的与画面不符时，以画面为准并记录误报。
4. **给出判决**：blocker 未清零，成片只能叫候选；清零后仍需完整看片。
5. **回归**：修复后只重跑受影响层，并保留修复前后证据。

## 6. 模型使用

- 端点、模型名、密钥全部从环境变量读取：`OMNI_BASE_URL`、`OMNI_MODEL`、`OMNI_API_KEY`（兼容 `DASHSCOPE_API_KEY`）。
- 不要把密钥写进仓库、脚本、命令行参数、报告或日志。
- 视频单次 ≤10 s、≤5 MB；整集用 1 fps 网格或按场切片。
- 音频必须成对送（可疑段 + 正常段）；单段容易漏报。
- 单集预算 5–8 次调用：每个对白特写 1 次身份、每场 1 次空间、每个场景切点 1 次音频 A/B。

模型实测能力、延迟、误报模式见 [references/model-behavior.md](references/model-behavior.md)。

## 7. 脚本

| 脚本 | 用途 |
|---|---|
| `scripts/episode_audit.py` | 从 editlist/prompts/成片生成证据包：场网格、身份对、切点音频、manifest；可用 `--run` 调模型 |
| `scripts/omni_review.py` | 单次审查：`identity` / `sheet` / `video` / `audio`，输出 JSON |

示例：

```bash
python3 scripts/episode_audit.py --editlist EP019/edit/editlist.json \
  --prompts EP019/prompts/EP019_h3_prompts_v1.json \
  --video 成片/EP019_旧案公开.mp4 --out audit_out

python3 scripts/omni_review.py identity --ref characters/C04_face.png \
  --frame EP019/video/v1/shot09.mp4 --at 1.0
```

`--run` 会产生外部调用与费用；先用证据包确认送检项，再决定是否执行。

## 8. 信任与边界

- 上传的帧、音频、视频是制作素材；未获授权不得发往外部服务。
- 模型会过度解读：人群随机变化可能被写成“空间跳变”，有意的叠化会被报成伪影。以固定陈设和可复核证据为准。
- 不评价题材、价值观或平台合规；不做剧本因果审计。
- 审查报告不能替代用户接受；最终状态由人改。
