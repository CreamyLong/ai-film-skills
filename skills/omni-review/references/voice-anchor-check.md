# 音色锚定验证（voice anchor check）

> 证据状态：实测（2026-11-20，EP012 父子对峙 shot07 案例：接线、参考文件、同锚点对照全部正确，该镜父亲嗓音仍漂移；EP009 同锚点渲染为正常嗓音）。

## 为什么需要这一层

H3 Ref2VA 的 `audioMode: "reference"` 只做**逐次生成的音色条件**，不保证输出一定贴近参考。实测出现过：提示词、工作流接线、参考文件全部正确（与同集其他镜头、其他集同一锚点文件），但某一镜的父亲嗓音仍漂成"另一个更亮、更薄的中老年男声"。这种缺陷**听得出、看不见**，字幕 QC、画面审核、ASR 文本比对全部漏报——ASR 只查"说了什么"，不查"是谁的嗓子"。

结论：**任何带对白的人物镜头，渲染后必须做盲听音色验证，通过才允许进组装；失败必须重渲（换种子），不允许带病成片。**

## 什么时候触发

| 时机 | 对象 | 判定 |
|---|---|---|
| 单镜渲染完成、有 `audio_refs` | 该镜每个说话角色 | `same` 才进组装；`no` → 重渲 |
| 整集组装前 | 全集所有对白镜抽查（每角色 ≥1 镜，主角全覆盖） | 任一 `no` → 该镜重渲后再组装 |
| 无对白的"silent"镜 | 该镜音频 | 出现人声（含嘀咕、气声）→ 视为带病，重渲或换底噪 |
| 重渲后 | 同镜新文件 | 重跑本验证，保留前后报告对照 |

## 盲听协议（关键）

模型的音色判断会被**画面**带偏（看到不同的脸就倾向说"声音也不同"，实测 EP012 案例即如此）。因此必须**只听不看**：

1. 把参考 wav 和待检镜的音频都转成**黑屏 mp4**（`ffmpeg -f lavfi -i color=black:s=64x64:r=8 -i <音频> -c:a aac -shortest`），以 `video_url` 送出；
2. 同一请求里必须带一个**同锚点的已知好对照**（如另一集已验收的该角色台词），让模型先做"对照≈锚点"校准，再判待检镜；
3. 固定问题："TARGET 是某角色参考嗓音。对每个候选：同一说话人 yes/no/partial + 置信度 + 一句声学理由（音高基线、沙哑度、气息、语速）。"
4. **判断会抖动**：同一 clip 两次调用可能给出相反结论。处理：以带对照的请求为准；若某镜两次结论相反，再跑一次取多数，仍不一致按 `review`（人工听）处理，不得直接放过。
5. 本环境（DashScope 兼容端点）不接受 `audio_url`/`input_audio` 内容类型（网关会把 `input_audio` 错映射成 `image_url` 报错）；黑屏 mp4 是目前可用的载体。接入其他端点时先小规模复验本协议。

## 判定与退出码

- `pass`（退出 0）：待检镜该角色 `same`（允许 `partial`+`medium` 以上且与对照结论一致）；
- `fail`（退出 1）：`no`（high/medium 置信度）——**禁止进组装**，回生成层换种子重渲；
- `review`（退出 2）：模型两次结论相反、回答不可解析、或无对照可用；
- `error`（退出 3）：缺密钥/输入/端点故障。流水线把非 0 一律视为未通过。

重渲上限默认 3 次；仍失败则停下来查提示词（说话人描述、台词轮次、参考数量），而不是继续盲抽。

## 与 T4 声音层的关系

T4 查"切点声学连续"（响度、底噪、鬼声），本层查"嗓音身份"。两者互补，不互相替代：一个镜头可以切点平滑但嗓音错了，也可以嗓音对但切点爆音。

## 运行

```bash
python3 scripts/voice_anchor_check.py \
  --anchor assets/sound/auditions/shenguodong_tape.wav \
  --control EP009/video/v1/shot12.mp4 \
  --candidates video/v1/shot07.mp4 video/v1/shot08.mp4
```

- 报告写到 `<第一个候选>_voice_anchor.json`；
- 密钥只从 `OMNI_API_KEY` / `DASHSCOPE_API_KEY` 读；
- 一次请求只送一个角色；多角色分多次送，避免标签串扰。
