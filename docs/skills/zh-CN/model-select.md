<!-- contract:purpose -->
## 1. 设计目的

按当前产物选择生成模型、参数与回退顺序：静帧与关键帧、单镜视频、多参考身份、长镜分段、角色配音与音乐。

<!-- contract:principles -->
## 2. 设计理念

- 选型从产物与验收标准出发，不从模型名气出发。
- 能力边界比参数更重要：先写清不要用的情况，再调参数。
- 一致性来自单一来源：同场不混源，同角色不混声。

<!-- contract:standalone -->
## 3. 适合单独使用的范围

当点名结果落在以下边界内时，可以只拿这一个模块使用：

可复现的选型结论：路线、模型标识、参数、禁止项与回退顺序；不产出媒体。

**单独不能声称:** 不提供模型、账号、额度或部署，不保证目标环境存在某个型号，也不认证成片质量。

<!-- contract:inputs -->
## 4. 输入

- 本次要交付的产物、目标画幅/时长/采样率，以及验收标准。
- 实际可用模型清单与部署状态，以及本地或云端执行的授权与费用边界。

<!-- contract:workflow -->
## 5. 流程逻辑

1. 按产物分流，给出首选、备选，以及两者都不该使用的情况。
2. 核对部署状态；未实测或未部署的能力按不可用处理，进生产前先做单变量小样。
3. 记录可复现的选型：模型标识、适配器、步数、cfg、画布、帧数与种子。

<!-- contract:returns -->
## 6. 退回、重做与版本回滚

- 输出失败先退回选型层：路线选错、参数超出模型契约、或参考素材不足。
- 不把换模型当成万能修复；先定位最早错误层再换路线。

<!-- contract:review -->
## 7. 审核门

- [ ] 每次对照只改一个变量，并保留对照结果。
- [ ] 交付前确认同场同源、同角色同声。
- [ ] 只写模型名、却无法按记录的标识与参数复现的选型不算完成。

<!-- contract:pass -->
## 8. 过关标准与状态

- 产物达到验收标准，且选型记录可复现。
- 存在回退路线，且未验证能力没有进入生产。

> 下方“通过”只表示本模块规定的审核门已通过；结构有效、真实任务证据和用户接受必须分开记录。

<!-- contract:outputs -->
## 9. 输出

- 选型结论：路线、模型标识、参数、禁止项与回退顺序。
- 必要时附单变量小样与对照结论。

<!-- contract:boundaries -->
## 10. 边界、依赖与权限

- 不提供模型、账号、额度或部署能力；清单以目标环境实际提供的为准。
- 不替代导演、资产或配音决定，也不认证成片质量。

<!-- contract:agents -->
## 11. 跨 Agent 使用

- 标准包是完整 Skill 文件夹，不是只复制一段提示词。
- `agents/openai.yaml` 只是 Codex 的可选界面元数据，不是其他宿主的运行依赖。
- 任何能读文件的宿主都能输出文字选型；真正执行所选路线还需要目标环境实际具备的模型、媒体工具与授权。
- Agent 能阅读指令不等于原生发现或原生执行；提示词回退不能写成原生兼容。
