<!-- contract:purpose -->
## 1. 设计目的

定义可复用的声音身份：角色音色（选角、声源、可听特征、样音组、演绎基线）、环境声底、标志音效或音乐主题，并记录权利与状态。

<!-- contract:principles -->
## 2. 设计理念

- 先建立可审核、可版本化的声音身份，再进入配音、原生音视频生成或混音。
- 音色资产回答“谁在说”，逐句演绎回答“这一句怎么说”；情绪不是新音色。
- 一个说话人在一部作品里只有一个已审音色源，剧本中的全部别名都映射到它；换源等于换人。
- 真人参考、克隆、上传、付费生成与商业交付是各自独立的授权，并随权利证据记录。
- 只有跨镜头或跨场次复用的声音才做成资产；一次性拟音和单场配乐剪辑留在该场声音设计里。
- 局部修订复用未变原文与相关上下文；资产编号留内部，未审样音限制正式配音，不阻断候选文字设计。
- 音色通过声源、可听特征、别名、权利和故事时间状态追踪，不能只靠预设名。

<!-- contract:standalone -->
## 3. 适合单独使用的范围

当点名结果落在以下边界内时，可以只拿这一个模块使用：

声音设计、逐条撰写的试音或样音任务，以及后续配音或生成可读取的合同；仅在有请求、有能力且已授权时产出实际样音。

**单独不能声称:** 不负责全片配音、逐镜对时或混音，也不能证明成片中的音色一致；这些需要实听实际制作音频。

<!-- contract:inputs -->
## 4. 输入

- 确立每个说话人年龄、地域、身体状态、关系与时间线的剧本或描述，以及实际阅读范围。
- 资产类别（角色音色、环境声底、标志音效、音乐主题）、唯一编号、版本、用途和仍未知字段。
- 已选或候选的音色路线、可用工具、已批准的参考音频，以及各项重要动作的权利与授权状态。

<!-- contract:workflow -->
## 5. 流程逻辑

1. 先选择设计文本、实际样音或局部诊断交付以及资产类别，再使用模板。
2. 从人物或空间事实推导可听特征；区分剧本事实、设计推定与关键未知。
3. 核对同场说话人只凭听觉可以分开，并把全部别名归一到一个说话人。
4. 规划参考样音组（中性基准、力度上限与下限、长句连读）或声底、音效、主题样音，逐条撰写试音文本。
5. 记录音色路线、声源标识或参考哈希、复现设置、权利与授权，生成机读资产合同。
6. 仅文本交付时可听检查保持not_evaluated；实际样音失败才标rework，资产需用户明确审听才能批准。

<!-- contract:returns -->
## 6. 退回、重做与版本回滚

- 年龄感、性别感或口音不符退回设计依据；角色之间分不开退回选角。
- 同一角色跨片段像换了人，退回路线与绑定：声源是否真的挂入请求，是否有说话人被静默跳过。
- 台词缺声退回别名映射与声源标识；念出指导语退回指令与台词的分离。
- 审核失败保持 `rework`，结构完成不能自动晋级。

<!-- contract:review -->
## 7. 审核门

- [ ] 编号、版本、类别、用途、说话人别名、锁定特征、音色源、权利和未知项明确。
- [ ] 同组样音听起来是同一个人，重复合成稳定，试音文本逐字念出且不含指导语。
- [ ] 语音样音为单人干声；声底可循环且无剧情事件；音效为单一干净事件；主题可辨认且不指名模仿作品或音乐人。
- [ ] 文件时长、采样率、声道与哈希来自实测；语音识别回读与说话人相似度是证据而非批准，缺工具时标未验证。
- [ ] 每个有台词的角色有且仅有一个音色源；年龄感与口音符合人物；同场角色可区分；权利与各项授权无歧义。

<!-- contract:pass -->
## 8. 过关标准与状态

- 样音任务和 JSON 合同通过模块检查，没有未解决阻塞字段或未授权动作。
- `assets_approved` 必须由用户审听按路径与哈希标识的实际样音；只有文本合同仍是待审状态。

> 下方“通过”只表示本模块规定的审核门已通过；结构有效、真实任务证据和用户接受必须分开记录。

<!-- contract:outputs -->
## 9. 输出

- 按请求范围交付带试音文本与演绎基线的音色设计，或环境声底、标志音效、音乐主题的样音任务。
- 供配音、提示词、混音和质检使用的版本化 JSON 声音资产合同，含声源、权利、审听与状态字段。

<!-- contract:boundaries -->
## 10. 边界、依赖与权限

- 禁止编写或运行批量生成提示词的脚本，不得循环套模板、替换变量、拼接正文或批量调用模型代写。完整提示词须逐项撰写复核，脚本只可校验或原样保存已完成正文；编译、事后润色和多条请求均不构成例外。
- 不臆造缺失事实、不覆盖批准特征，也不把具体镜头的台词时间窗、口型或混音电平写进资产身份。
- 没有音频工具、授权和审听时，本模块交付样音任务与合同，不能声称完成或批准音频。
- 安装或运行本模块不授予声音权、克隆许可、上传许可、付费额度或音乐权利。

<!-- contract:agents -->
## 11. 跨 Agent 使用

- 标准包是完整 Skill 文件夹，不是只复制一段提示词。
- `agents/openai.yaml` 只是 Codex 的可选界面元数据，不是其他宿主的运行依赖。
- 任何能读取文件夹的宿主都可输出文本合同；真实样音还需要语音、音效或音乐工具、文件能力、相应权利与授权，以及人类审听。
- Agent 能阅读指令不等于原生发现或原生执行；提示词回退不能写成原生兼容。
